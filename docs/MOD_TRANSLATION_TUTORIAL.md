# KOTOR II MOD 汉化教程：提取、翻译与打包

本教程面向希望汉化其他 MOD 或修正本体文字的玩家。工具只写入新工程和新补丁目录，不覆盖原 MOD、主 `dialog.tlk` 或存档，也不会把 DLL 放进汉化包。

## 下载工具

- [Windows 可视化工具 0.2.0（ZIP）](../downloads/KOTOR2_MODTranslator_020.zip)：解压后运行 **KOTOR2_MOD汉化工作台.exe**，无需安装 Python。
- [工具源码](../tools/mod_translation_gui.py)，Python 3.10+ 用户可在仓库根目录运行 `python tools/mod_translation_gui.py`。
- [简体中文本地化 MOD](https://steamcommunity.com/sharedfiles/filedetails/?id=3816191703)
- [共享原生组件](https://steamcommunity.com/sharedfiles/filedetails/?id=3816551034)：独立 TLK 译文包需要支持自动挂载的接口候选。
- [夹克汉化测试案例](https://steamcommunity.com/sharedfiles/filedetails/?id=3818950577)及其[原作](https://steamcommunity.com/sharedfiles/filedetails/?id=2853389296)。

接口和工具仍处于测试阶段。离线检查通过不等于任意 MOD 的实机兼容性通过。请先制作小型补丁，再在副本存档中验证。

## 一、准备原 MOD

将下载的 MOD 解压到单独文件夹；工坊 MOD 通常位于 `SteamLibrary/steamapps/workshop/content/208580/条目编号`。选择原作目录，不能选已经汉化或已经经过绑定的补丁目录。

工具目前支持松散 GFF 资源中的本地化字符串，例如 `.uti` 物品名称/说明、`.utc` 角色名称、`.dlg` 局部对白和 `.jrl` 日志，以及 TLK 编号文本。它会保留 GFF 原有编号、其他语言/性别、语音字段和非文本属性。

`.mod/.rim/.erf` 容器需先通过合法的 KOTOR 资源工具提取目标 GFF 文件；工具会提示这些容器未自动处理。2DA 的普通字符串、脚本内文本、普通 CExoString 和自定义格式也未自动提取。不同模块里的同名资源不能直接混放到全局 override，需要作者判断模块作用域或单独合并，工具遇到重复文件名会阻止打包。

## 二、提取与填写译文

1. 启动工具，选择 **MOD 汉化** 和原 MOD 文件夹。
2. 如果文本引用 TLK 编号，选择该 MOD 实际使用的**英文 TLK**；MOD 自带根目录 `dialog.tlk` 时可自动识别。不要把中文 TLK 当作英文原文。
3. 点击 **提取文本**。列表显示资源、字段、语言/性别或编号，英文原文只读。查看提取提示，避免误认为未支持的文本也已提取。
4. 输入唯一工程标识，例如 `myname.carthjacket.chs`。它用于补丁目录和报告，不是工坊编号。
5. 选择条目，在下方填写中文，点击 **应用译文**或按 `Ctrl+Enter`。切换条目也会保留编辑内容。搜索框支持按原文、译文和资源名筛选，列表每页250条。
6. `Ctrl+S` 保存翻译工程，之后可用 **打开工程**继续。工程是本地 JSON，包含原文、资源路径、来源摘要及译文，不应连同个人路径直接上传。

可以点击 **导出 CSV**，只编辑 `zh` 列，再用 **导入译文 CSV**批量回填。不要修改 `key` 或 `source`；导入时会核对它们，防止把译文填给错误条目。

请完整保留 `<CUSTOM0>`、`<FullName>`、`%d` 等变量。工具会检查变量、原文摘要和当前字形映射；缺少字形时会停止打包并列出字符。不要自行改成 UTF-8 字节写入游戏资源。新增字形需要主汉化共同扩展，而不是单独替换旧字体。

## AI 一键翻译

点击 **API 设置**，填写 OpenAI 兼容服务的基础地址、模型和 API 密钥。例如基础地址可为服务商提供的 `https://…/v1`，也可填写完整 `/chat/completions` 地址。模型按服务商实际提供的名称填写，工具不会替你选择或购买模型。

可调整每批条数（1–20）、翻译提示词，或启用服务支持的 JSON 模式。密钥默认仅本次会话使用；勾选记住时用 Windows DPAPI 按当前系统用户加密保存。配置位于本机用户目录，不会进入工程、独立MOD或ZIP。

点击 **AI 一键翻译未译条目**，会将未翻译原文发送到你配置的服务。请求可能产生服务商费用。已有译文不会覆盖；每批会校验条目标识、JSON结果和变量。生成结果标为 AI 草稿，需人工复核姓名、语境和性别；缺字会在打包时阻止输出。

**停止 AI** 会在当前请求结束后停止后续批次。已完成批次保留；已有工程文件时每批保存进度。遇到 API 错误时不要重建工程，检查配置后继续即可。工具没有替你提供 API 账号或额度，也不会用项目人员的密钥替你调用。

协议实现参考 [OpenAI Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)，不要求只使用 OpenAI 服务。尚未使用用户真实密钥验证各外部服务；测试使用本地模拟服务。

## 三、打包 MOD 局部汉化

点击 **打包汉化补丁**，选择一个输出父目录。工具会生成一个新目录和同名 ZIP，生成一个可独立发布的汉化 MOD，只包含已填写译文对应的资源、MOD 名称与前置清单、工坊标题/说明草稿及验证报告。填写“独立 MOD 名称”和“原 MOD 链接”后再打包。工具不自动订阅或发布工坊条目。

未填写译文的字段保持原样。GFF 局部补丁使用主汉化字形编码，不引入新的全局编号，因此没有跨作者虚拟编号分配的问题。原资源改变后，旧工程会拒绝继续打包，需重新提取与复核。

典型输出：

```text
myname.carthjacket.chs-chs/
  override/carthjacket.uti
  README-CHS.txt
  translation-report.json
  mod-manifest.json
  workshop/title.txt
  workshop/description.txt
```

直接使用主汉化字体的局部资源补丁无需逐MOD安装器。夹克工坊测试案例采用另一种独立引用绑定路径，用来验证共享接口，不必把其原始资源绑定脚本当作本工具的默认流程。

## 四、本体文本修正或已有 TLK 编号覆盖

1. 选择 **原版文本修正**。
2. 原文选择合法安装中的英文 TLK。使用合并版汉化时，应优先选择英文前置 `1402798020/dialog.tlk`，不能仅按相同编号套用另一版本的译文。
3. 在 **当前主汉化 TLK** 中选择 `3816191703/dialog.tlk`，用于验证当前中文表与原文的对应关系。
4. 提取后搜索要修正的条目、填写新译文，再打包。

工具使用当前公开的来源摘要表检查编号对应关系，保存英文和当前中文的匹配版本，并生成：

```text
myname.textfix-chs/
  localization/chs-overlay.ini
  localization/translation.chsp
  README-CHS.txt
  translation-report.json
  mod-manifest.json
  workshop/title.txt
  workshop/description.txt
```

不会重新打包主 TLK。原生接口保留该编号原有语音，遇到两个包对同一原文给出不同译文时会回退，而不是静默抢占。

这种方式适用于当前主汉化已经识别的原文和编号，不能自动把任意 MOD 的完整 TLK、新增编号或脚本引用合并进本体。未知来源会拒绝打包；这类 MOD 应使用局部资源补丁或单独设计编号迁移。

## 五、安装、测试与发布

需要原 MOD、主汉化及正确加载顺序：同名资源的汉化补丁应优先于原作，避免原英文文件覆盖译文。不要同时加载两个完整 `dialog.tlk` 汉化覆盖包。

独立 `.chsp` 译文包由[公共原生组件](https://steamcommunity.com/sharedfiles/filedetails/?id=3816551034)提供的共享 DLL 读取。已有旧入口的用户需更新一次根目录 DLL；各汉化补丁不提供 DLL，也不再要求各自运行安装器。当前自动挂载候选位于公共组件 `bootstrap/text-interface-candidate`，普通0.1.3不具备自动发现功能。

接口只读取 Steam 当前启用并已下载完成的订阅，以及各补丁的翻译清单。手动解压一个 `.chsp` 文件到任意目录不会自动挂载。测试独立包可先上传自己的工坊测试条目、订阅并重启；工具只打包，不会替你上传或发布。

局部资源补丁也可在备份并检查冲突后手动复制到游戏 override 中测试。工具不自动复制到游戏；请勿在游戏运行中改动资源。

旧存档会缓存物品、角色和对白文字。优先使用新获得的物品、新进入的区域或独立测试副本；不要把“旧物品没变化”直接当作打包失败。测试夹克时可用 `giveitem carthjacket`，原作限定男性主角或门徒、需要轻甲熟练，不要让阿顿装备这一版本。

发布前核对原作者的补丁/再发布条件，注明原 MOD 前置、版本、修改资源、冲突及获取方式。不要重打包原作模型、贴图或本体完整资源，不要附带个人存档、工程中的本机路径、DLL或账号资料。项目代码MIT许可不授予原MOD或游戏内容的所有权。

停用补丁并重启后会停止加载其独立译文包，但存档缓存不会自动回滚；共享DLL升级或主字体变化后也需要重新核验兼容性。

## 常见问题

- **没有提取到文字**：检查是否选了原作目录；查看容器/格式提示；若GFF引用编号，提供正确英文TLK。
- **来源不匹配**：原MOD或主表变动，重新提取，不要直接修改SHA绕过检查。
- **变量不匹配或缺字**：保留全部变量，处理缺字提示后重试。
- **输出目录已存在**：换一个新目录，工具不会覆盖旧补丁。
- **两个目录有同名文件**：先判断模块作用域，不能直接把两者都放进override。
- **独立包没有加载**：确认使用支持自动挂载的共享DLL，补丁已订阅并启用、下载完成且已重启；详细结果在游戏根目录HighFPS-loader.log中。
